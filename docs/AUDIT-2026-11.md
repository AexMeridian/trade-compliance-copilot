# Expert audit, November 2026

Eight simulated senior practitioners audited the site and code on 2026-11-20 and 2026-11-21: customs broker, export-controls and sanctions counsel, trade economist, international-relations scholar, data engineer/SRE, application-security tester, product designer, and accessibility/performance engineer. They were read-only: nothing was changed, and the calculator was never run.
Full individual reports (with evidence and sources) were written to the session scratchpad as `audit-1-broker.md` to `audit-8-a11y-perf.md`. This file is the merged, de-duplicated list.

Caveats on the audit itself: the customs broker could not read federalregister.gov (it blocks automated fetches), so annex product lists and the Section 232 proclamation text are unverified. The SRE could not confirm the remote database directly. Treat each finding as "verify, then fix", not as settled.

## Reliability and security

- SDN, HTS and similar bulk loads exceed free-plan limits: HTS makes 96 fetches against a 50 cap and can never succeed on the Worker (L, or a GitHub Action loader at M).
- D1 write budget counts rows, not writes; when the cap is hit, logging and spend counters fail too (M).
- Spend controls fail open if D1 errors; the Anthropic console limit is the real backstop (S, owner).
- One person can use up the shared 300-calls-a-day cap (a screening makes up to 10 model calls) and take the calculator offline mid-demo: per-IP daily quota plus an owner demo token (M).
- `POST /api/pulse/sync` is public and unauthenticated (S).
- Case links are bearer links with no privacy statement; names and descriptions are stored 30 days (M).
- Public data-status leaks raw upstream error text; grounding error text is echoed to clients (S).
- Staleness alerts cover only 10 sources; Treasury partial failure still advances lastSuccess (S).
- Unapplied-migration behavior: health summary can freeze; migration tests only regex-check files (M). `npm audit`: 6 root findings (dev-only) (S). Add `permissions: contents: read` to workflows (S). Prompt-injection regression tests (S).
- Test gaps: scheduled() end to end, healthRun, notify, per-job fetch budgets, spend fail-open.
